# 검증

변경을 검증하거나 작업 완료 여부를 판단할 때 적용한다.

## 검증 선택

- 요청의 완료 조건, 변경 범위와 회귀 위험에 맞춰 검증 방법을 선택한다.
- 기존 테스트와 프로젝트의 실행 경로를 활용한다.
- 기존 검증이 놓치는 구체적인 회귀를 확인해야 할 때 필요한 테스트를 추가한다.
- 검증 방법, 대상 커밋과 실행 결과를 기록한다.

## 변경별 확인

| 변경 | 확인할 내용 |
|---|---|
| C# 코드 | 컴파일, 정상 진입 경로, 변경된 호출자와 기존 동작 |
| 데이터 | 로딩, 변환, ID 연결과 기존 데이터 및 에셋의 호환성 |
| 전투 | 실제 생성과 발사 경로, 다중 객체, 충돌, 사망과 풀 재사용 |
| 게임 진행 | 초기화, 씬 전환, 웨이브와 완료 조건, 재진입 |
| UI와 카메라 | 표시, 입력, 팝업 순서, 콜백과 추적 동작 |
| Unity 에셋 | `.meta`, GUID, 직렬화 참조, 실제 씬과 프리팹 연결 |
| 아트 | 규격, 기존 아트와의 일관성, 실제 표시 크기의 가독성 |
| 문서 | 합의 내용과의 일치, 경로와 링크, 문서 사이의 규칙 일관성 |

## 결과와 후속 변경

- 실패 원인과 재현 조건을 기록하고, 수정 후 영향을 받는 검증을 다시 수행한다.
- 검증 이후 코드가 변경되면 새 대상 커밋과 필요한 재검증 범위를 확인한다.
- 검증 완료 여부는 실제 수행 결과를 근거로 판단한다.
- 실행한 검증, 결과와 미검증 범위를 완료 보고에 기록하고, PLAN 작업에서는 원본에도 반영한다.
- 도구나 실행 환경의 제한으로 확인하지 못한 항목은 이유와 함께 남긴다.
