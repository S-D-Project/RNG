# 워커

배정받은 구현, 검증, 코드리뷰 또는 PR 작업에 적용한다. 독립 실행에서도 같은 작업 기준을 사용한다.

## 작업 확인

- [workflow.md](workflow.md)를 읽고 PLAN 적용 여부와 배정된 작업을 확인한다.
- 목표, 완료 조건, 변경 소유 범위, 워크트리와 브랜치를 확인한다.
- PLAN을 사용하는 작업은 `source`가 가리키는 원본의 `active` 상태와 현재 배정을 확인하고, 하위 작업을 해당 PLAN의 승인 범위에 따라 진행한다.
- 오케스트레이션에서는 오케스트레이터가 `ready` PLAN을 인수하여 `active`로 전환한 뒤 배정한 작업을 수행한다.
- 작업 영역의 지침과 기존 구현을 확인한 뒤 실행한다.

## 작업 유형

| 유형 | 수행 내용 | 전달할 결과 |
|---|---|---|
| 구현 | 배정 범위의 코드·에셋·설정·문서를 변경하고 결과를 확인한다. | 변경 커밋, 구현 내용과 확인한 동작 |
| 검증 | 지정된 커밋을 [verification.md](verification.md)에 따라 확인한다. | 대상 커밋, 수행 방법, 결과와 미검증 범위 |
| 코드리뷰 | 요구사항 충족, 결함, 회귀 가능성, 상태와 책임의 일관성을 검토한다. | 대상 커밋, 근거와 위치가 있는 지적 사항, 보완 확인 결과 |
| PR | PLAN에서 PR을 사용하는 경우 변경·검증·리뷰 결과를 모아 [github.md](github.md)에 따라 PR을 생성하고 갱신한다. | PR 링크, 연결된 PLAN과 사용자 확인 사항 |

## 인수인계

- 검증과 리뷰에서 발견한 수정 사항은 구현 담당자에게 전달한다.
- 변경 이후에는 해당 커밋을 기준으로 필요한 검증과 리뷰를 다시 수행한다.
- 결과에는 작업 범위, 브랜치와 대상 커밋, 수행 결과와 남은 작업을 포함한다. PLAN을 사용하는 작업은 식별자와 원본을 함께 전달한다.
- 범위 변경이나 진행을 막는 문제가 생기면 오케스트레이터 또는 독립 실행의 사용자에게 알린다.

## 독립 실행

- 새 로컬 PLAN은 [plans.md](../Plans/plans.md)에 따라 ID와 원본 경로를 정해 `proposed`로 작성하고, 사용자 승인 후 `active`로 전환한다.
- 이슈 등록은 선택 사항이다. 완료 기록은 기존 ID와 `completed`를 유지하고 원본 전환 후 진행 기록은 이슈에서만 관리한다.
- 한 에이전트가 요청한 산출물에 필요한 구현·검증·코드리뷰를 수행한다. PR 사용 여부는 PLAN의 완료 조건에 명시한다.
- 저장소 반영을 위한 코드·에셋·설정·문서 변경은 PR을 기본으로 삼고, 조회·분석·검토·제안은 PR 없이 완료할 수 있다. 부수적인 PLAN·README 갱신만으로 PR 요구를 추가하지 않는다.
- 실제 수행한 검증과 리뷰 방식, 별도 담당자의 참여 여부를 기록한다.
- PR의 최종 리뷰와 머지는 사용자가 담당한다.
