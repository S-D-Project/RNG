# GitHub와 작업 환경

GitHub 이슈, 워크트리, 브랜치와 PR을 사용하는 작업에 적용한다. 상태, 승인과 원본 관리는 [plans.md](../Plans/plans.md)를 따른다.

## 저장소와 PLAN 정보

- GitHub 작업은 `gh` CLI를 사용하고 연결된 저장소와 인증 상태를 확인한다. 조회와 갱신에는 대상 저장소를 명시한다.
- 이슈에는 `PLAN metadata` 영역의 단일 YAML 코드 블록에 `id`, `status`, `current_step`, `source`를 기록한다. 이슈 제목은 PLAN 제목으로 사용한다.
- 작성 양식은 [Feature](../../.github/ISSUE_TEMPLATE/feature.yml), [Bugfix](../../.github/ISSUE_TEMPLATE/bugfix.yml), [Refactor](../../.github/ISSUE_TEMPLATE/refactor.yml), [Documents](../../.github/ISSUE_TEMPLATE/documents.yml)를 따른다. CLI로 등록할 때도 같은 메타데이터 영역을 포함한다.
- 신규 실행 요청의 기본값은 `status: ready`, `current_step: 배정 대기`이다. 사용자가 새 작업이나 `proposed` PLAN을 `ready`로 제출하도록 요청한 행위는 실행 승인으로 취급한다.
- 신규 GitHub PLAN의 빈 ID와 `source`는 등록 담당자 또는 최초 수집 담당자가 인수 전에 발급·확정하고 이슈 본문에 기록한다. `source`는 해당 이슈 URL로 설정한다.
- 기존 PLAN 등록에는 기존 ID가 필수다. 기존 ID를 재발급하거나 이미 지정된 다른 원본을 임의로 덮어쓰지 않고 원본 전환 절차를 따른다.
- 메타데이터의 필드와 상태를 검증한다. 누락·잘못된 상태를 `ready`로 해석하지 않으며, 이슈 열림·닫힘이나 라벨로 PLAN 상태를 대신 판단하지 않는다.

## 기존 PLAN 등록과 원본 전환

- 이슈 등록은 선택 사항이다. 기록 목적 등록은 최초 본문부터 기존 ID와 상태를 유지하고, 완료된 로컬 PLAN은 `completed`와 완료 결과를 포함한다.
- 로컬 `proposed` PLAN의 실행 요청은 원본 전환 후 `ready`로 제출한다. 기록 목적 등록은 `proposed`를 유지한다.
- 이슈 URL을 확인한 뒤 이슈와 로컬 파일의 `source`를 해당 URL로 맞춘다. 로컬 파일은 이관 시점의 기록과 원본 링크를 보관하고 이후 진행은 이슈에서만 갱신한다.
- 진행 중인 작업을 인계할 때는 기존 담당자의 실행을 정리하고 남은 작업을 기록한다. 원본 전환이 완료된 뒤 `ready`로 전환한다.
- 이미 연결된 이슈가 있으면 같은 이슈를 갱신한다. PLAN ID, 이슈 번호와 README 등록 순서는 구분한다.

## 워크트리와 브랜치

- 각 작업은 담당 워크트리에서 진행하고 브랜치와 작업 소유자를 특정한다. 배정된 워크트리가 있으면 해당 경로와 브랜치를 확인해 사용한다.
- Git Flow에 따라 `develop`을 기준으로 `feature/<PLAN-ID>-<기능>` 브랜치를 만들고 PR 대상도 `develop`으로 설정한다.
- 같은 PLAN의 하위 작업은 기능명으로 브랜치 범위를 구분한다. 명시적인 비 PLAN 작업은 `feature/no-plan-<기능>`을 사용한다.
- 워크트리는 실행 환경의 관리 기능을 통해 생성·관리한다. 병렬 검증과 리뷰는 각자의 작업 공간에서 지정된 대상 커밋을 확인한다.

## 커밋과 PR

- 저장소에 반영할 코드·에셋·설정·문서 변경은 PR을 기본 완료 조건으로 삼고, 조회·분석·검토·제안은 PR 없이 완료할 수 있다.
- PR 사용 여부를 PLAN의 완료 조건에 명시한다. 부수적인 PLAN·README 관리 기록 갱신만으로 PR 요구를 추가하지 않는다.
- 커밋에는 담당 작업의 변경만 포함하고 푸시할 저장소와 브랜치를 확인한다.
- PR을 사용하는 작업은 검증·코드리뷰 결과를 확인한 뒤 에이전트가 PR을 생성하고 갱신한다.
- PR 본문은 [저장소 템플릿](../../.github/pull_request_template.md)을 따르고 변경 내용, 검증 결과, 미검증 범위와 PLAN 또는 이슈를 연결한다.
- 하위 작업 PR은 담당 범위를 명시한다. 전체 완료 조건을 충족하는 PR에 종료 연결을 사용하고 실제 머지와 완료 조건을 확인한다.
- 피드백과 후속 변경을 반영하여 PR 설명과 검증 결과를 갱신한다. 최종 PR 리뷰와 머지는 사용자가 담당한다.
- 완료 조건을 확인하고 PR을 사용하는 작업은 사용자 머지까지 확인한 뒤 PLAN 상태와 이력을 갱신한다.
