# 코드 작성 규칙

C# 코드의 작성과 수정에 적용한다.

## 명명과 형식

- 타입, 메서드, 프로퍼티와 상수는 `PascalCase`를 사용한다.
- private 인스턴스 필드는 `_camelCase`, 매개변수와 지역변수는 `camelCase`를 사용한다.
- 외부 데이터와 대응하는 DTO 필드명은 데이터 계약을 따른다.
- 들여쓰기는 공백 4칸을 사용하고, 중괄호는 다음 줄에 배치한다.
- 수정하는 범위에서 인접 코드의 형식을 따르고, 변경 범위에 필요한 서식만 정리한다.
- 변수와 메서드는 역할이 드러나는 이름으로 작성하고, 조건과 상태 변경을 읽기 쉽게 표현한다.

## 파일과 공개 범위

- 파일명은 주요 타입명에 맞춘다. 작은 보조 타입은 사용 범위와 기존 배치를 고려해 함께 둔다.
- 외부에서 필요한 멤버만 공개하고, 직렬화 필드와 공개 프로퍼티의 역할을 구분한다.
- 기존 데이터 모델의 필드와 프로퍼티 형태를 확인한 뒤 변경한다.
- namespace, 어셈블리와 공용 타입 배치 변경은 [architecture.md](architecture.md)에 따라 영향을 검토한다.

## Unity 코드

- 인스펙터 설정과 오브젝트 참조는 기존 직렬화 방식에 맞춘다.
- 다형성 설정은 해당 데이터 모델의 `[SerializeReference]` 구성을 따른다.
- Unity 이벤트 메서드에는 해당 생명주기의 처리를 두고, 기능의 초기화와 실행 책임을 명확히 한다.
- 직렬화 필드와 타입 변경은 [unity-assets.md](unity-assets.md)를 함께 따른다.

## 주석

- 코드만으로 알기 어려운 이유, 제약과 외부 계약을 설명한다.
- 주석은 현재 동작과 일치하도록 갱신한다.
