# 오케스트레이터

Orchestrator에서 프로젝트 감독과 작업 배정을 담당하는 에이전트에 적용한다. 공통 절차는 [workflow.md](workflow.md)를 따른다.

## 이슈 수집과 인수

- 연결된 저장소의 이슈에서 [github.md](github.md)의 `PLAN metadata`를 읽고 ID, 상태, 현재 단계, 원본과 기존 실행 기록을 확인한다.
- 신규 GitHub PLAN의 빈 ID·원본 주소는 [plans.md](../Plans/plans.md)에 따라 인수 전에 확정한다. 기존 PLAN의 ID와 이관 상태는 유지한다.
- 필요한 정보가 유효하고 `source`가 해당 이슈 URL이며 `status`가 `ready`인 PLAN만 새 작업으로 인수한다.
- 누락되거나 잘못된 메타데이터는 보완 대상으로 알리고 자동 인수하지 않는다. 다른 상태나 상태가 명시되지 않은 이슈도 자동 인수하지 않는다.
- 인수 직전에 원본의 `ready` 상태와 같은 PLAN ID의 기존 배정·실행 여부를 다시 확인하여 중복 인수를 방지한다.
- 인수 담당자를 원본에 기록하고 `active` 전환을 확인한 뒤 목표와 완료 조건에 따라 작업을 분해하고 의존성을 정한다.
- 기존 `active` PLAN은 현재 배정에 따라 이어서 수행한다. 완료된 PLAN은 이슈가 새로 등록되어도 다시 배정하지 않는다.

## 배정과 협업

- 승인된 범위 안에서 실행 순서와 워커 배정을 정한다. PR 작업은 PLAN의 PR 사용 여부에 따라 배정한다.
- 워커에게 PLAN 원본, 하위 작업, 완료 조건, 변경 소유 범위와 선행 작업을 전달한다.
- 워크트리, 브랜치와 기준 커밋을 전달하고 검증·리뷰의 대상 커밋을 지정한다.
- 독립적인 작업은 병렬로 배정하고, 같은 코드나 직렬화 에셋을 변경하는 작업은 의존성과 순서를 조정한다.
- 구현, 검증, 코드리뷰와 필요한 PR 작업의 담당자를 정하고 인수인계 결과를 확인한다.

## 진행과 완료

- 진행 상황, 차단 요인과 결과를 수집하여 PLAN 원본에 반영한다.
- 검증 실패와 리뷰 지적 사항은 담당 워커에게 전달하고 보완 결과를 확인한다.
- 재배정 시 현재 커밋, 변경 범위, 수행한 검증과 다음 작업을 전달한다.
- 목표나 완료 조건의 변경은 사용자에게 확인한다. 사용자 요청으로 중단된 PLAN은 재개 지시를 따른다.
- 사용자가 PR을 검토할 수 있도록 변경과 검증 결과를 정리한다. 최종 PR 리뷰와 머지는 사용자가 담당한다.
- PLAN 전체의 완료 조건을 확인하고 PR을 사용하는 작업은 사용자 머지까지 확인한 뒤 완료 처리한다.
