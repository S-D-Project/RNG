# 게임 데이터

데이터 정의, 로딩, 결합, 실행 상태와 데이터 계약을 변경할 때 적용한다.

## 데이터 역할

| 구성 | 역할 |
|---|---|
| `DTO` | Google Sheets에서 읽는 필드와 수치 |
| `Resource` | 프리팹, 아이콘과 동작 설정 |
| `Registry` | ID를 통한 리소스 검색 |
| `Builder` | DTO와 리소스를 결합하여 기본 Data 생성 |
| `Data` | 실행 객체가 참조하는 기본 데이터 |
| `Runtime` | 개별 실행 객체의 현재 상태 |

## 로딩과 계약

- 시트 헤더와 DTO public 필드명의 대응을 확인한다.
- DTO, 리소스, Registry와 소비 코드가 사용하는 ID를 일치시킨다.
- 로더, 파서, Builder, `GameDataStore`와 실제 소비 경로를 함께 확인한다.
- 필수 데이터의 누락, 중복과 형식 오류가 어느 단계에서 처리되는지 확인한다.
- 프리팹에서 읽는 충돌 반경과 컴포넌트 참조도 데이터 구성의 일부로 취급한다.

## 기본 데이터와 실행 상태

- 공유되는 기본 데이터와 개별 객체가 변경하는 실행 상태의 소유권을 구분한다.
- 실행 상태는 생성과 초기화 시 설정하고, 풀 재사용 시 필요한 값을 다시 초기화한다.
- 설정 객체가 실행 객체를 생성하는 기존 흐름과 생성 단위를 확인한 뒤 변경한다.
- 기존 에셋과 데이터가 새 코드에서도 올바르게 로드되는지 확인한다.

## 구조 변경과 결정 기록

- 필드, ID 계약, 데이터 구조나 상태 소유권을 변경할 때 관련 파서, Builder, 소비 코드와 직렬화 에셋을 확인한다.
- 에이전트는 [decisions.md](../Decisions/decisions.md)에 따라 게임 데이터 구조 변경에 대한 판단 근거를 `Docs/Decisions/`에 기록한다.
- 개별 결정 기록의 작성과 갱신, 결정 README의 행 추가와 갱신은 별도 사용자 승인 없이 수행한다.
- 기록에는 변경 대상, 이유, 검토한 대안, 선택한 방식과 기존 데이터 및 코드의 영향 범위를 담는다.
- 관련 결정 기록을 읽고 후속 변경에 반영한다.
- 직렬화 변경은 [unity-assets.md](unity-assets.md), 동작 검증은 [verification.md](verification.md)를 따른다.
