# 지침 추가와 수정

지침의 추가 또는 수정 필요성을 판단하고 변경안을 제안할 때 적용한다.

## 변경 후보

- 여러 작업에서 같은 요청, 절차나 수정 요구가 반복되면 지침 개선 후보로 평가한다.
- 사용자가 지속적으로 적용할 규칙을 요청하면 변경 후보로 다룬다.
- 승인된 구조나 데이터 계약의 변경으로 기존 지침을 갱신해야 하는지 확인한다.

## 판단 기준

- 같은 종류의 후속 작업에 재사용할 수 있는 규칙인지 확인한다.
- 사용자의 명시적 요구, 승인된 결정과 확인된 작업 방식을 근거로 삼는다.
- 적용 조건과 에이전트의 행동을 짧고 명확하게 작성할 수 있어야 한다.
- 기존 문서의 책임에 해당하면 해당 문서를 보완한다. 독립적인 적용 범위가 있으면 새 문서를 제안한다.

## 승인과 반영

1. 기존 지침과 비교하여 대상 파일과 변경 범위를 정한다.
2. 사용자에게 대상 파일, 제안 문구, 적용 범위와 필요한 이유를 제시한다.
3. 지침의 추가와 수정은 사용자 승인을 받은 뒤 수행한다. 이미 명시적으로 승인된 변경은 해당 범위에서 반영한다.
4. 승인된 내용을 반영하고 파일의 줄 수를 확인한 뒤 필요한 Map 연결을 갱신한다.

## 본문 기준

- 각 지침 파일은 제목과 빈 줄을 포함하여 최대 100줄로 작성한다.
- 지침에는 적용 범위와 핵심 규칙만 작성한다.
- 추가 경위와 상세한 필요성은 승인 제안에서 설명한다.
- 매우 특수한 예외와 개별 작업 사례를 지침 본문에 누적하지 않는다.
- 루트 `AGENTS.md`는 적용 조건과 읽을 문서의 경로를 안내하는 Map 역할을 맡는다.

## 승인 예외

### PLAN 이력

- 승인된 [PLAN 관리 규칙](../Plans/plans.md)에 따른 [README.md](../Plans/README.md)의 행 추가와 현재 상태 갱신은 별도 승인 없이 수행한다.
- README에는 순서, 상태, 제목, 간단한 내용 네 항목만 기록한다.
- 승인 근거, 상세 진행과 검증 결과 및 관련 링크는 PLAN 원본에 기록한다.

### 결정 기록

- [결정 기록 규칙](../Decisions/decisions.md)에 따른 개별 결정 기록의 작성과 갱신은 에이전트 판단으로 별도 사용자 승인 없이 수행한다.
- [결정 README](../Decisions/README.md)의 행 추가와 갱신도 별도 승인 없이 수행한다.
- 결정 README에는 순서, 제목, 간단한 내용 세 항목만 기록한다.
- 변경 이유, 판단 근거와 관련 링크는 개별 결정 기록에 둔다.
