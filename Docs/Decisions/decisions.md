# 데이터 구조 결정 기록

게임 데이터 구조를 변경하거나 관련 결정 기록을 작성, 갱신할 때 이 문서를 읽는다. 데이터 작업 기준은 [data.md](../agents/data.md)를 따른다.

## 기록 대상

- DTO 필드와 시트 데이터 계약의 변경
- Resource, Registry, Data와 Runtime의 구조 또는 관계 변경
- ID 체계, 직렬화 방식과 데이터 호환성 변경
- 공유 데이터와 개별 실행 상태의 소유권 변경

## 작성과 갱신

- 승인된 작업 범위에서 데이터 구조를 변경할 때 에이전트가 판단 근거를 기록한다.
- 개별 결정 기록의 작성과 갱신, README의 행 추가와 갱신은 에이전트 판단으로 별도 사용자 승인 없이 수행한다.
- 변경 중 판단 근거를 남기고, 작업을 마칠 때 실제 구현과 일치하도록 갱신한다.
- 새 ID는 `decision-YYYYMMDD-xxxxxxxx`로 만든다. 날짜는 KST 생성일, `xxxxxxxx`는 도구로 생성한 소문자 16진수 난수 8자리이며, 등록 전 기존 기록과 중복을 확인한다.
- ID는 최초 확정 후 유지하며 제목이나 관련 PLAN이 바뀌어도 재발급하지 않는다.
- 하나의 결정은 `Docs/Decisions/<ID>-<주제>.md` 파일로 관리한다. README 등록 순서는 ID와 구분한다.
- 관련 PLAN, 이슈, PR과 상세 참조는 개별 결정 기록에 연결한다.

## 기록 내용

| 항목 | 내용 |
|---|---|
| 변경 사항 | 어떤 데이터 구조를 어떻게 바꾸었는지 |
| 변경 이유 | 해결하려는 문제와 요구사항 |
| 판단 근거 | 선택을 뒷받침하는 코드, 데이터와 확인 결과 |
| 검토한 대안 | 실제 검토한 대안과 선택 이유 |
| 영향 범위 | 관련 코드와 에셋, 호환성과 이관 필요사항 |

## 기존 결정의 변경

- 관련 결정 기록을 먼저 확인하고 후속 작업에 반영한다.
- 기존 결정을 대체할 때는 새 기록에 이전 기록과 변경 이유를 연결한다.
- 이전 기록에도 대체한 기록을 연결하고 당시 판단 근거를 보존한다.

## README 관리

- [README.md](README.md)에는 `순서`, `제목`, `간단한 내용` 세 열의 표만 둔다.
- 결정마다 한 행을 등록하고 최초 등록 순서를 유지한다.
- 제목은 결정 기록의 제목을 사용하고, 간단한 내용은 핵심 결정을 한 문장으로 작성한다.
- 기록이 갱신되면 해당 행을 맞추고, 대체된 결정도 목록에 유지한다.
- 상세 근거와 관련 링크는 개별 결정 기록에 둔다.
